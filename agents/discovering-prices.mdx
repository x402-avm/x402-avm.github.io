## The price is in the 402

x402 has no separate price list. The server states the price of a specific call in the `402 Payment Required` response to that call, in the `PAYMENT-REQUIRED` header. With `PaymentGate` the price can depend on the tool, its arguments and the caller (see [Pricing](/ai-economy-sdk/pricing)), so the same tool can cost different amounts for different inputs.

MCP's `tools/list` returns names, descriptions and input schemas, but no prices. A vendor may mention prices in tool descriptions; treat those as informative, and the `402` as authoritative.

The decoded header looks like this:

```json
{
  "x402Version": 2,
  "accepts": [
    {
      "scheme": "exact",
      "network": "algorand:wGHE2Pwdvd7S12BL5FaOP20EGYesN73k",
      "asset": "31566704",
      "amount": "50000",
      "payTo": "VENDOR_ADDRESS",
      "maxTimeoutSeconds": 300,
      "extra": { "decimals": 6, "feePayer": "FEE_PAYER_ADDRESS" }
    }
  ]
}
```

Read it as: pay 50,000 base units of asset 31566704 (0.05 USDC, 6 decimals) on MainNet to `VENDOR_ADDRESS`, with fees sponsored by `FEE_PAYER_ADDRESS`. `accepts` can hold several offers, for example one per network; a client pays one of them.

## With paid_mcp_session

`paid_mcp_session` reads the `402` and pays automatically when the offer passes its spend controls. The agent does not see the price, only the result, and the spend cap is its upper bound on any single call. That is the recommended setup for most agents: choose a cap you are willing to pay for any one call.

## Inspecting a price before paying

When an agent must decide per call, for example to compare vendors or ask a person to approve, read the challenge without paying:

1. Send the request with a client that does not pay.
2. On `402`, decode `PAYMENT-REQUIRED`.
3. Decide, then pay by retrying with `PAYMENT-SIGNATURE`.

For HTTP APIs this is a plain request:

<CodeGroup>
```python Python
import httpx
from x402.http import decode_payment_required_header

response = httpx.get(url)
if response.status_code == 402:
    required = decode_payment_required_header(response.headers["payment-required"])
    for offer in required.accepts:
        print(offer.network, offer.asset, offer.amount, offer.pay_to)
```

```ts JavaScript
import { decodePaymentRequired, selectRequirement } from 'x402-avm-js';

const res = await fetch(url);
if (res.status === 402) {
  const required = decodePaymentRequired(res.headers.get('PAYMENT-REQUIRED')!);
  const offer = selectRequirement(required, 'mainnet'); // throws if nothing is offered on MainNet
  console.log(offer.amount, offer.asset, offer.payTo);
}
```
</CodeGroup>

For an MCP server behind `PaymentGate`, the challenge is the HTTP response to the `POST` that carries the `tools/call`. The MCP SDK's client does not surface that HTTP response to your code. With a server on the Streamable HTTP transport (stateless, the default of `gate.wrap(mcp, transport="streamable-http")`), you can ask for the price with one plain HTTP request, without the MCP `initialize` handshake:

```python
import base64, json
import httpx

call = {"jsonrpc": "2.0", "id": 1, "method": "tools/call",
        "params": {"name": "echo", "arguments": {"text": "hi"}}}
r = httpx.post("http://127.0.0.1:9201/mcp", json=call,
               headers={"Accept": "application/json, text/event-stream"})
if r.status_code == 402:
    offer = json.loads(base64.b64decode(r.headers["payment-required"]))["accepts"][0]
    print(offer["amount"], offer["asset"], offer["payTo"])
```

Nothing is paid or signed. On the legacy SSE transport the same request goes to the session's `/messages/?session_id=...` endpoint, so you would have to speak SSE at the HTTP level. Unless you need per-call approval, rely on spend controls instead. Every field of the challenge is described on [HTTP 402 response reference](/resources/http-402-reference).

## Policies for x402 clients

With an `x402Client` from the official SDK (for HTTP APIs), a payment policy sees every offer before one is chosen and can drop offers. A policy is a function `(x402_version, requirements) -> requirements`; if it removes them all, the client raises `NoMatchingRequirementsError` and pays nothing.

```python
from x402 import x402Client
from x402_algorand.exact.register import register_exact_avm_client

MAX_BASE_UNITS = 20_000

def cheap_only(version, requirements):
    return [r for r in requirements if int(r.amount) <= MAX_BASE_UNITS]

client = x402Client()
register_exact_avm_client(client, signer, policies=[cheap_only])
```

`paid_mcp_session` builds its own client and takes `spend_controls`, not policies.
