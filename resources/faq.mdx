title: "FAQ"
description: "Short answers to common questions about x402 on Algorand and the x402-avm packages, with links to the full explanation."
---

<AccordionGroup>
  <Accordion title="What is x402?">
    An open protocol that sells a resource per request with HTTP status `402 Payment Required`: the server states the price, the client retries with a signed payment, the server settles. See [How it works](/how-it-works).
  </Accordion>
  <Accordion title="What is the exact scheme on Algorand?">
    The x402 scheme in which the client pays exactly the requested amount of one asset to one address, as an Algorand atomic group. See [AVM exact scheme](/reference/protocol/avm-exact-scheme).
  </Accordion>
  <Accordion title="Why does the payment group have two transactions, and who pays the fees?">
    Transaction 0 is the server's fee payer covering the fees of both; transaction 1 is the buyer's payment with fee 0. The server pays 2,000 microALGO per settled call, so the buyer pays exactly the price. See [the atomic group](/how-it-works#the-two-transaction-atomic-group).
  </Accordion>
  <Accordion title="What is the lowest price I can charge in ALGO?">
    More than 2,000 microALGO; 3,000 is a sensible minimum. `PaymentGate` refuses lower fixed ALGO prices unless you pass `allow_loss=True`. The floor does not apply to USDC. See [the fee floor](/build/pricing#the-fee-floor).
  </Accordion>
  <Accordion title="How can buyers pay in USDC if fees are in ALGO?">
    The fee payer pays the ALGO fees in the same group, so the buyer needs no ALGO beyond its minimum balance. Both sides must opt in to USDC first. See [Accept USDC](/production/mainnet#accept-usdc).
  </Accordion>
  <Accordion title="What is the minimum balance requirement?">
    Every Algorand account must hold 0.1 ALGO, plus 0.1 ALGO per opted-in asset (applications add more), and cannot spend below it.
  </Accordion>
  <Accordion title="When is a payment settled, and what if the tool fails?">
    After the tool succeeds. If it fails, the signed payment is discarded and the buyer is not charged. See [Settle-on-success](/how-it-works#settle-on-success).
  </Accordion>
  <Accordion title="How does replay protection work with several workers?">
    Pass `replay_db="/path/replay.db"` so every worker shares one SQLite store. See [Replay store](/production/security#replay-store).
  </Accordion>
  <Accordion title="How is a pass different from a per-call payment?">
    A pass is one payment with the note `x402-pass:<scope>` that makes calls in that scope free for a period (30 days by default). See [Passes](/how-it-works#passes).
  </Accordion>
  <Accordion title="Can an identity proof move my funds?">
    No. It is a 0-amount payment to yourself with fee 0 and an expired validity window, so the network will never accept it. See [Identity](/build/identity).
  </Accordion>
  <Accordion title="Which wallets work with x402-avm-js?">
    Any wallet that signs Algorand transactions given the encoded transactions and the indexes to sign, for example through `@txnlab/use-wallet-react` (Pera, Defly, Lute, KMD and others), or a local key in Node. See [Connect a wallet](/build/pay-from-browser#connect-a-wallet).
  </Accordion>
  <Accordion title="How long does a payment take?">
    The server returns the result after the group is confirmed in a block, usually a few seconds. Algorand blocks are final once confirmed, with no forks to wait out.
  </Accordion>
  <Accordion title="Can an AI agent pay for tools safely?">
    Within limits you set: a dedicated wallet with a small balance, and spend controls that cap each payment. See [AI agents](/build/ai-agents#set-limits).
  </Accordion>
  <Accordion title="How do I move from LocalNet to MainNet?">
    Follow [Networks](/production/networks) to TestNet, then the [go-live checklist](/production/mainnet#go-live-checklist).
  </Accordion>
</AccordionGroup>
