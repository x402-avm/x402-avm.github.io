```bash
npm install x402-avm-js algosdk @txnlab/use-wallet-react
```

Add the wallet providers your app supports (see the use-wallet documentation).

## The signing callback

`payForRequirement` hands signing to a callback:

```ts
signTxns: (txns: Uint8Array[], indexes: number[]) => Promise<(Uint8Array | null)[]>
```

`txns` are the encoded unsigned transactions of the group and `indexes` the ones the buyer must sign. The callback must return an array of the same length as `txns`, with the signed bytes at each index in `indexes` and `null` elsewhere. Unsigned positions are sent as they are, for the server to sign.

Wallets return signatures in one of two shapes:

1. **Full group:** an array as long as `txns`, with `null` at positions not signed.
2. **Sparse:** an array as long as `indexes`, holding only the signed transactions.

This wrapper normalizes both:

```ts
const safeSignTxns = async (txns: Uint8Array[], indexes: number[]): Promise<(Uint8Array | null)[]> => {
  const signed = await signTransactions(txns, indexes);
  const mapped: (Uint8Array | null)[] = new Array(txns.length).fill(null);
  if (!signed) return mapped;
  if (signed.length === indexes.length) {
    indexes.forEach((txnIdx, i) => { mapped[txnIdx] = signed[i]; });
  } else {
    signed.forEach((bytes, i) => { if (bytes) mapped[i] = bytes; });
  }
  return mapped;
};
```

## Example with use-wallet

{/* example: localnet/browser_wallet.ts */}

```typescript localnet/browser_wallet.ts expandable
/**
 * React browser wallet integration using use-wallet-react v5 and x402-avm-js.
 *
 * Demonstrates:
 * 1. Connecting to active wallet account, algod client, and signTransactions hook.
 * 2. Normalizing the signTransactions return contract across different wallet providers.
 * 3. Calling payForRequirement() to fulfill an x402 payment challenge.
 *
 * How to type-check:
 *   npx tsc --noEmit localnet/browser_wallet.ts
 */

import { useWallet } from '@txnlab/use-wallet-react';
import {
  payForRequirement,
  type PaymentRequired,
} from 'x402-avm-js';

/**
 * Execute an x402 payment challenge using the connected browser wallet.
 *
 * Different wallet providers implement the signTransactions contract in two ways:
 * - Full-group mapping: Returns an array of length equal to txns.length, with null at un-signed indexes.
 * - Sparse mapping: Returns an array of length equal to indexes.length, containing only requested signatures.
 *
 * The wrapper normalizes both behaviors to match payForRequirement's expectation:
 * an array of length txns.length with Uint8Array at signed indexes and null elsewhere.
 *
 * @param challenge - Decoded PaymentRequired challenge from HTTP 402 response.
 * @param wallet - useWallet() hook return value.
 * @returns Promise resolving to the base64-encoded PAYMENT-SIGNATURE header.
 */
export async function payWithBrowserWallet(
  challenge: PaymentRequired,
  wallet: ReturnType<typeof useWallet>
): Promise<string> {
  const { activeAddress, algodClient, signTransactions } = wallet;

  if (!activeAddress) {
    throw new Error('No active wallet connected. Please connect your wallet first.');
  }

  // Normalize wallet signing response to full group length
  const safeSignTxns = async (
    txns: Uint8Array[],
    indexes: number[]
  ): Promise<(Uint8Array | null)[]> => {
    const signed = await signTransactions(txns, indexes);
    if (!signed) {
      return new Array(txns.length).fill(null);
    }

    const mapped: (Uint8Array | null)[] = new Array(txns.length).fill(null);
    if (signed.length === indexes.length) {
      indexes.forEach((txnIdx, signIdx) => {
        mapped[txnIdx] = signed[signIdx];
      });
    } else {
      signed.forEach((signedBytes, idx) => {
        if (signedBytes) {
          mapped[idx] = signedBytes;
        }
      });
    }
    return mapped;
  };

  return await payForRequirement(
    challenge,
    activeAddress,
    algodClient,
    safeSignTxns
  );
}
```

## What happens when you pay

1. `payForRequirement` fetches suggested parameters from algod (`algod.getTransactionParams().do()`).
2. It picks the `exact` offer for algod's network with `selectRequirement`, and throws if there is none.
3. It builds the group with `buildExactAvmGroup`:
   - With `extra.feePayer`: transaction 0 is the server's 0-amount self-payment with a pooled fee of twice the minimum fee (2,000 microALGO), and transaction 1 is your payment with fee 0.
   - Without it: one payment that pays the normal fee.
4. The wallet asks the user to sign only the buyer's transaction.
5. The signed and unsigned transactions are encoded into the `PAYMENT-SIGNATURE` header.

The browser submits nothing to the chain. The server verifies the group, runs the service, and settles only if the service succeeds.
