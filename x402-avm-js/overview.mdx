`x402-avm-js` (npm, MIT, version 0.4.0) is a TypeScript library for the client side of the Algorand exact scheme. It decodes a `402` challenge, picks the offer for your wallet's network, builds the payment group, has any wallet sign its part, and encodes the `PAYMENT-SIGNATURE` header. It works on MainNet, TestNet, LocalNet and private networks, with ALGO or any ASA such as USDC.

```bash
npm install x402-avm-js@0.4.0 algosdk
```

## Pay a 402 response

```ts
import { algodClient, decodePaymentRequired, payForRequirement } from 'x402-avm-js';

const algod = algodClient('mainnet'); // or 'testnet', or algodClient(network, url, token)
const res = await fetch(url);
if (res.status === 402) {
  const required = decodePaymentRequired(res.headers.get('PAYMENT-REQUIRED')!);
  const header = await payForRequirement(
    required,
    myAddress,
    algod,
    (txns, indexes) => wallet.signTransactions(txns, indexes), // Pera, Defly, Lute, KMD, a local key...
    { maxAmount: 50_000n, allowedNetworks: ['mainnet'] },      // spend controls, checked before signing
  );
  const paid = await fetch(url, { headers: { 'PAYMENT-SIGNATURE': header } });
}
```

`payForRequirement` pays the offer for the network that `algod` is on. A server can offer several networks, for example MainNet USDC and TestNet ALGO. If none of the offers is on the wallet's network, the call throws instead of signing a payment the server cannot use.

No transaction is submitted by the client. The server verifies the signed group, runs the service, and submits the group.

## Spend controls

The server chooses the amount in a `402`, so a compromised or buggy server could ask for any amount. `payForRequirement` and `buildExactAvmGroup` check every offer against spend controls **before anything is built or signed**:

- **By default, any payment above 1,000,000 base units (1 ALGO, or 1 USDC) is refused** with `SpendLimitExceededError`. This matches the default of the official Python x402 client.
- `maxAmount` sets the cap (one value, or per asset id); `Infinity` removes it.
- `allowedAssets`, `allowedNetworks` and `allowedPayTo` restrict what may be paid; anything else is refused with `PaymentNotAllowedError`.

The options, with examples: [Guardrails](/agents/guardrails#javascript-clients).

## Errors

Every error extends `X402AvmError` and carries a stable `code`: `SpendLimitExceededError`, `PaymentNotAllowedError`, `InvalidPaymentRequiredError`, `NoSupportedRequirementError`, `NetworkMismatchError`, `UnknownNetworkError`, `InvalidOptionsError`. `decodePaymentRequired` and `parsePaymentRequired` validate untrusted input and throw `InvalidPaymentRequiredError` for a malformed challenge. Errors from algod or from your signing callback propagate unchanged. When each is thrown: [Errors and error codes](/resources/error-codes#x402-avm-js-errors).

## Runtimes

The library uses only standard web APIs (`Uint8Array`, `TextEncoder`, `TextDecoder`) and imports no Node built-ins, so it runs in browsers, Node.js 20+, web workers and edge runtimes without polyfills. It is published as an ES module.

## Upgrading to 0.4

- **Default spend cap.** Payments above 1,000,000 base units are now refused. To pay more, pass `{ maxAmount: ... }` as the last argument of `payForRequirement` or `buildExactAvmGroup`.
- **Node.js 20 or later.** Node.js 18 is no longer supported.
- **Validation.** `decodePaymentRequired` validates the decoded shape and throws `InvalidPaymentRequiredError` (0.3 returned whatever JSON it found). `selectRequirement`, `encodePaymentHeader` and `payForRequirement` take `PaymentRequired` instead of `PaymentRequired | any`; `extra` and `extensions` values are `unknown` instead of `any`.
- **Typed errors.** Catch `X402AvmError` subclasses or check `error.code` instead of matching messages.

## Migrating from 0.2

0.3 uses the Algorand CAIP-2 profile for network ids (`algorand:` plus 32 URL-safe base64 characters): `algorand:wGHE2Pwdvd7S12BL5FaOP20EGYesN73k` for MainNet and `algorand:SGO1GKSzyE7IEPItTxCByw9x8FmnrCDe` for TestNet. Legacy 44-character ids are still accepted by `resolveNetwork` and `selectRequirement`, so existing servers keep working.

## Testing the package

```bash
npm test                 # offline tests
PUBLIC_NETS=1 npm test   # also builds payments on TestNet and MainNet and simulates them (no keys, no funds)
LOCALNET=1 npm test      # also settles real payments on a running LocalNet
```
